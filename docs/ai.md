# AI Architecture

## Difficulty ladder

| Level | Name | Decision model |
| --- | --- | --- |
| 0 | 新手 | 基础合法出牌与较高随机性 |
| 1 | 进阶 | 手牌成本与结构整理 |
| 2 | 高手 | 记牌、队友让牌与危险拦截 |
| 3 | 职业 | 团队感知 SO-ISMCTS，生产预算 240ms |
| 4 | 戴长胜 | 更高搜索预算和自对弈调优的风格先验，生产预算 420ms |

高档 AI 仍共享同一套规则引擎。搜索只能选择规则层已经确认合法的牌型，不能生成或解释新的规则。

## Information boundary

根玩家可使用：

- 自己的实际手牌；
- 四家的公开剩余张数；
- 已出牌、过牌、报牌和当前牌墩；
- 公开的进贡、还贡和抗贡事件；
- 当前级牌、两队比赛级别和历史名次。

搜索不得读取对手真实手牌。每次模拟从完整 108 张牌池移除已出牌、根玩家手牌和仍公开归属的贡还牌，再按公开手牌数重新分配隐藏牌。

公开贡还牌是硬约束。对手桌顶存在合法高牌时选择过牌只作为软证据，因为玩家可能保牌或让队友；所有合法归属始终保持非零概率。

## Team-aware SO-ISMCTS

搜索树保存公开动作序列，不绑定某一次随机生成的隐藏牌：

1. 每次模拟重新采样一个与根玩家信息一致的世界。
2. 沿共享的公开动作树选择或扩展动作。
3. 根玩家与队友节点最大化根队价值，对手节点最小化根队价值。
4. 子动作只在当前采样世界合法时参与选择，并累计 availability。
5. 使用轻量 rollout 到终局或上限，回传升级、名次、控场和剩余牌力价值。

这种结构避免“单次猜牌决定整棵树”和“对手帮助根玩家”两类确定化 MCTS 偏差。

## Action policy

树搜索不会简单截取成本最低的前 N 手。候选池固定保留以下代表：

- 立即出完；
- 过牌；
- 最低成本合法压制；
- 最大减手结构；
- 强控场非炸弹；
- 各正常牌型的低成本代表；
- 最小和最大合法炸弹。

节点通过 progressive widening 随访问次数增加动作。风格参数只改变动作先验，不会在搜索结束后把选择结果直接改成过牌。

## Runtime budgets

生产游戏使用时钟预算，保证 GUI/TUI 后台 AI 的单步等待有上限。Arena 的 `--deterministic-search` 使用两档搜索上限作为固定模拟数，消除机器速度对动作序列的影响：职业 64 次，戴长胜 96 次。

固定迭代适合代码回归，生产预算适合实际体验评估。二者模拟数不同，胜率不能直接混合统计。

## Evaluation

公平强度测试必须对同一 seed 连打两局，并交换候选与基线所在固定队：

```bash
python -m guandan.ai.arena \
  --candidate 4 --baseline 3 \
  --deals 20 --seed-start 5000 --json
```

发布前整场门禁增加 `--full-match`，从级牌 2 连续执行升级、进贡、还贡和过 A。主要指标是整场胜率，margin 使用比赛结果 `+1/-1`，因为获胜队过 A 后级牌会重置到 2；单局模式才报告真实升级差。两种模式都会输出 Wilson 95% 区间、Elo 估计及候选 AI 的决策延迟。

戴长胜风格参数通过两阶段自对弈筛选，并用未参与调参的 seed 留出验证：

```bash
python -m guandan.ai.tuning \
  --candidates 6 --screening-deals 3 \
  --finalists 2 --final-deals 10 \
  --output tuning-report.json
```

调参双方使用成本受控的 28 / 48 次固定迭代，避免 CPU 负载改变候选排序；入选参数再以 64 / 96 次完整上限和生产时钟预算分别验收。调参报告和当前留出摘要位于 `benchmarks/`。小样本胜率必须连同置信区间阅读，不能仅凭一轮胜场调整正式 Profile。

# AI Architecture

## Difficulty ladder

| Level | Name | Decision model |
| --- | --- | --- |
| 0 | 新手 | 基础合法出牌与较高随机性 |
| 1 | 进阶 | 手牌成本与结构整理 |
| 2 | 高手 | 记牌、队友让牌与危险拦截 |
| 3 | 职业 | 32 次配对根动作评估，生产预算 240ms |
| 4 | 戴长胜 | 96 次配对根动作评估和风格先验，生产预算 420ms |

当前最高档自对弈选中的风格先验等于职业档的中性值，能力目标是以更高预算提高团队胜率；不把未经验证的炸弹或过牌偏好硬编码进生产决策。高档 AI 的过牌由搜索选择，不使用随机过牌倍率。

高档 AI 仍共享同一套规则引擎。搜索只能选择规则层已经确认合法的牌型，不能生成或解释新的规则。

## Information boundary

根玩家可使用：

- 自己的实际手牌；
- 四家的公开剩余张数；
- 已出牌、过牌、报牌和当前牌墩；
- 公开的进贡、还贡和抗贡事件；
- 当前级牌、两队比赛级别和历史名次。

搜索不得读取对手真实手牌。每次模拟从完整 108 张牌池移除已出牌、根玩家手牌和仍公开归属的贡还牌，再按公开手牌数重新分配隐藏牌。

公开贡还牌是硬约束。对手桌顶存在合法高牌时选择过牌只作为软证据，因为玩家可能保牌或让队友；所有合法归属始终保持非零概率。

## Paired root-action evaluation

生产搜索把有限预算直接用于比较当前动作：

1. 每轮重新采样一个与根玩家信息一致的世界。
2. 所有根动作都应用到该世界的独立副本，形成低方差的配对比较。
3. 每个动作使用轻量 rollout，到终局或上限后返回根队价值。
4. 预算均匀分配；两次采样后逐步淘汰的方案在 200 局面基线上更差，因此不采用。
5. 返回平均价值最高的根动作；风格先验只作随访问次数衰减的弱修正。

根动作副本使用引擎的轻量搜索克隆函数，并用固定种子回归确认动作及各候选均值与深拷贝一致。一个 70 手后的样本局面上，32 次评估用时由 126ms 降至 79ms；这是局部性能读数，实际收益仍以生产时钟预算下的模拟数和延迟为准。

旧的团队感知 SO-ISMCTS 仍可通过 `search_mode="tree"` 启用，供回归与研究使用，
但不再是生产默认。200 局面基线中，平坦根评估在更低延迟下优于或持平于旧树搜索。

## Action policy

根评估不会简单截取成本最低的前 N 手。候选池固定保留以下代表：

- 立即出完；
- 过牌；
- 最低成本合法压制；
- 最大减手结构；
- 强控场非炸弹；
- 各正常牌型的低成本代表；
- 最小和最大合法炸弹。

最多保留 6 个搜索候选，并额外确保合法过牌和 greedy 实际动作有值可比较。
风格参数只改变动作弱先验，不会在搜索结束后把选择结果直接改成过牌。

`scripts/action_value_baseline.py audit-candidates` 可将生产候选与所有合法实体出牌比较。首次 12 局面、每动作 200 次续局的审计中，候选池最优动作召回为 9/12，平均池外价值差 0.0096。样本较小，且从多个动作中取最大值会放大标签噪声；当前不据此扩大六动作预算，先用更多留出局面确认漏选是否稳定。

## Runtime budgets

生产游戏使用时钟预算，保证 GUI/TUI 后台 AI 的单步等待有上限。Arena 的 `--deterministic-search` 使用两档根动作评估上限，消除机器速度对动作序列的影响：职业 32 次，戴长胜 96 次。

固定迭代适合代码回归，生产预算适合实际体验评估。二者模拟数不同，胜率不能直接混合统计。

复杂牌型的定向 rollout 已作为实验模式保留（`rollout_strategy=3`），生产仍使用档 1。200 局面配对试验中，定向模式 regret 为 0.0537，对照为 0.0487，耗时 118.2ms 对 104.6ms；regret 差的 95% 区间跨 0，不支持启用。

## Evaluation

公平强度测试必须对同一 seed 连打两局，并交换候选与基线所在固定队：

```bash
python -m guandan.ai.arena \
  --candidate 4 --baseline 3 \
  --deals 20 --seed-start 5000 --json
```

发布前整场门禁增加 `--full-match`，从级牌 2 连续执行升级、进贡、还贡和过 A。主要指标是整场胜率，margin 使用比赛结果 `+1/-1`，因为获胜队过 A 后级牌会重置到 2；单局模式才报告真实升级差。两种模式都会输出 Wilson 95% 区间、Elo 估计及候选 AI 的决策延迟。

戴长胜风格参数通过两阶段自对弈筛选，并用未参与调参的 seed 留出验证：

```bash
python -m guandan.ai.tuning \
  --candidates 6 --screening-deals 3 \
  --finalists 2 --final-deals 10 \
  --output tuning-report.json
```

调参双方使用成本受控的 28 / 48 次固定评估，避免 CPU 负载改变候选排序；入选参数再以 32 / 96 次完整上限和生产时钟预算分别验收。调参报告和当前留出摘要位于 `benchmarks/`。小样本胜率必须连同置信区间阅读，不能仅凭一轮胜场调整正式 Profile。

另用 `evaluate-diverse` 在 2、9、A 级、四个座位及新手/高手对局来源各取均衡局面，并由高手策略续局打标签。首次 24 局面、每动作 100 次的留出结果：greedy / root32 / root96 平均 regret 分别为 0.0663 / 0.0575 / 0.0767；root32 与 greedy、root96 与 root32 的配对 95% 区间均跨 0。固定迭代、交换队伍的 8 个 seed（16 局）中，root96 对 root32 为 8:8。这些读数不足以宣称最高档有稳定棋力优势，后续参数调整须同时通过更大的留出集和整局复赛。

生产时钟下另测 4 个 seed（8 局）：最高档对职业档为 2:6，Wilson 95% 区间为 7.1%–59.1%，最高档决策 p95 为 377ms。样本仍不足以确认真实胜率，尤其不能据此单次改动配置。

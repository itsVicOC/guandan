# AI 出牌策略

## 五档阶梯

难度编号 `0..4` 保持不变；存档版本与迁移说明见 README。低档通过较少的信息与规划自然形成差距，不通过随机放弃好牌降智。所有 AI 的行动均由规则引擎验证。

| 档位 | 名称 | 决策 |
| --- | --- | --- |
| 0 | 新手 | 基础手牌整理、低成本回应、不过度消耗炸弹；无随机过牌 |
| 1 | 进阶 | 有界牌组规划，估算出牌后剩余手数与散牌 |
| 2 | 高手 | 公开记牌、控制牌保留、队友让牌与危险拦截 |
| 3 | 职业 | 全局面配对根动作评估；常规 1 秒、关键局面 2 秒 |
| 4 | 戴长胜 | 更多候选与采样，极短残局限时团队搜索；常规 2 秒、关键局面 5 秒 |

关键局面指任一在场玩家剩余不超过 10 张、需要回应炸弹，或本家存在一手出完的合法牌。档 3/4 的主搜索评估次数上限分别是 256/768；实际次数受时钟限制。戴长胜用整段预算比较候选，并采用考虑剩余牌组手数的截断估值。`SearchResult.budget_limited` 指示是否提前停下。旧 `hand_threshold` 参数仍可用于研究时关闭前期搜索，生产配置全程启用。

## 信息边界与选牌

根玩家只能使用自己的手牌、四家公开张数、已出/过牌历史、公开贡还牌、当前牌墩、级牌与比赛分数。搜索每轮从 108 张牌中扣掉自身手牌、已出牌及仍有公开归属的牌，再按公开张数重新分配三家暗牌。过牌仅作为软证据，不推定对手必定没有某牌。根决策和贡还牌选择不得读取真实暗牌。

进阶以上的手牌规划把规则引擎识别的牌型作为覆盖整手牌的候选，使用缓存、固定宽度和节点上限估计未来出牌手数。牌型枚举和基础结构估值也使用有容量上限的缓存，重复续局可复用结果；桌顶合法性与级牌比较仍逐次计算。当前出牌再考虑逢人配、控制牌及炸弹的机会成本。高手档结合已出牌和报牌数量：队友占桌顶时通常让牌，但在自己可大量减牌或必须拦截时可以接管；仅有炸弹可回应而对手尚不紧迫时通常保留炸弹。

高档根搜索保留一手出完、规划低成本、最低合法压制、最大减牌、强控场、不同牌型、最小/最大炸弹、合法过牌、贪心及快速战术参考动作。根动作按实体用牌区别，同点数不同花色可能影响剩余同花结构；树搜索历史仍按公开可见的牌型共享统计。一次出完若可能被对手压制，也参与动作比较。

每轮根评估为所有候选使用相同的假设暗牌世界；最终比较只用共同完成的世界，未完成的最后一次续局会被丢弃。先验被限制为小幅修正，不能压过明确的续局收益。搜索至少完成 6 轮共同评估并显示足够收益后，才替换快速战术判断；非紧急局面用炸需要更强证据。没有合法回应、只能过牌时直接返回，不启动搜索，也不消耗采样随机数。

职业档一般换牌的基础门槛为 0.14；最高档使用共同世界的配对标准误。第 3 版规则下，0.14/0.04/0.25/0.40 等实用门槛和先验均按本局六种名次结算的跨局收益跨度缩放，标准误已经处于实际收益单位，不再二次缩放。这样级别和失败次数改变后，固定门槛不会淹没整场目标。这是选牌启发式，并非多候选统计显著性保证。报告中的 `guard` 记录收益跨度、要求的差值、实际差值和配对误差。

续局策略会处理顺子、连对、钢板、三带二、保留对子/炸弹、报单拦截和队友接管。头游确定后，截断估值只估计余下名次对应的比赛价值，不能反转已经确定的头游方。最高档在全场剩余不超过 12 张时，先用最多 70% 的关键预算尝试终局搜索；未完成则用剩余时间回到根评估。实体用牌枚举接受超时检查，未完成的枚举不会进入缓存。置换表分别标记精确值、下界和上界，跨窗口复用时收紧窗口，不把剪枝界直接当作精确收益。固定工作量评测也执行该路径，保留 30,000 节点上限。

第 3 版规则使用 `scripts/fit_match_value.py` 拟合六种完整名次概率，再映射到 1,350 项跨局继续值表。输入覆盖双方不对称级别、A 失败次数、头游及贡还牌条件；概率与价值均满足队伍交换后的互补约束。768 副混合代理牌局按整副划分为 576 副训练和 192 副留出，模型约 60 KB，运行时只读表与线性权重。它预测代理续局的比赛价值，不是人类胜率。旧 `fit_ai_value.py` 及估值权重保留供历史规则和研究复查使用。

进贡和还贡仍由规则层确定合法集合。AI 仅在合法集合中选择：新手沿用简单选择，进阶以上尽量保全自己的牌组，并弱化对手可能受益的回贡牌；真人手选优先。GUI 和 TUI 的 AI 均在后台行动，TUI 每次展示一名 AI 的结果。

三次冲 A 下，真正过 A 的收益为 1/0；普通小局与失败后的收益取后继比赛状态的继续值，因此前两次失败和第三次退回 2 不再混为同一个终局。头游已定时按队友二、三、末游概率估值。历史规则仍保留原有目标。新增的 `partner_bomb_guard`、`team_tactics`、`lead_chain`、`heterogeneous_rollouts`、`endgame_confidence`、`endgame_policy` 分别控制长手无收益炸队友保护、协作战术、短回应链、搭档风格混合、八世界置信度和行动者局部信息续局。行动者局部信息续局始终标为策略采样结果；全知假设世界搜索只有在公开信息唯一确定暗牌且搜索完成时标为精确。默认开关与独立验证结果见 [本轮落地记录](ai-comprehensive-optimization.md)；第 2 版规则的[历史结果](ai-team-optimization.md)不用于新规则结论。

## 评测与门禁

`python -m guandan.ai.arena --candidate 2 --baseline 1 --deals 20 --seed-start 21000 --json` 对同一 seed 打两局并换队。区间按完整的两局 seed 对进行 bootstrap；不足 10 对时报告 `[0, 1]`，若有未完成局则退回 Wilson 区间。生产时钟模式用于体验与延迟，`--deterministic-search` 固定 256/768 次主搜索评估用于跨机器回归（最高档另含有节点上限的残局搜索），两种胜率不可混算。

整场门禁使用 `--full-match`，从 2 级连续经过升级、进贡、还贡和过 A。`scripts/action_value_baseline.py evaluate-ladder` 在 2/9/A 级、四个座位和两种来源策略收集局面，比较五档实际选牌、候选覆盖及 regret；`audit-candidates` 对照所有规则枚举动作。小样本续局标签只用于排查，不可用来宣称强度。发布前使用独立留出 seed，并事先确定样本规模或顺序检验方案；区间跨 50% 时只报告未证实，不按观察到的胜率持续扩样直到通过。新基准与未通过的实验见 [benchmarks/README.md](../benchmarks/README.md)。

### 固定回归与生产预算诊断

```bash
python -m guandan.ai.diagnostics --mode fixed \
  --baseline benchmarks/ai-regression-v6.json --output fixed.json
python -m guandan.ai.diagnostics --mode clock --output clock.json
python -m guandan.ai.diagnostics --mode curve --output curve.json
python -m guandan.ai.diagnostics --mode endgame-clock --output cold-solver.json
```

固定回归使用 2/9/A 级的开局和残局，共 6 个经事件重放校验的局面、五档 30 次决策；关闭时钟，保留 256/768 次工作量及残局节点上限。门禁校验动作合法性、选牌及决策原因，比较前检查规则、策略、配置和局面集版本。选牌变化须先审查再更新基线，不意味着所有变化都是退化。

生产时钟检查单独运行职业/戴长胜共 12 次决策，逐次按对应常规/关键预算的 `1.15 × 预算 + 100ms` 检查软时限。定时配对 8 seed 对仅作完成与合法性冒烟，不再据此判定棋力，也不套用固定工作量的绝对耗时门槛。完整比赛冒烟的 p95 容差为 5.85 秒，与最高档 5 秒关键预算一致。

诊断记录候选构造、隐藏世界采样、续局耗时、实际评估量、共同样本轮数、预算受限标志、选牌/回退原因及规划缓存命中、大小。阶段计时不含全部前后处理，不能简单相加作为端到端时间。报告另含代码 SHA、平台、Python、并发数和缓存条件。

预算曲线在同一进程按局面、档位、递增预算顺序运行，缓存保持热状态；动作与固定工作量参考一致的比例仅用于诊断，不能替代胜率或收益。后续实验应随机化预算顺序、增加独立重复与冷缓存对照，补充峰值内存、三家连续行动累计等待及独立配对比赛，再决定是否改默认预算。

历史的 32/96 评估、240/420ms 生产时限及旧胜率位于既有 `benchmarks/` 文件和 Git 历史，只用于回顾旧实现。新策略的基准必须重新建立，不可直接把旧时钟胜率与新固定迭代数据比较。

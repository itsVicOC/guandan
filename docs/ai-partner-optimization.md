# 搭档执行能力与牌权判断研究（2026-09-30）

本轮仅研究职业和戴长胜档，保持职业常规/关键 1/2 秒、戴长胜 2/5 秒预算，以及 256/768 次主搜索工作量上限。前三档、游戏规则、存档与 `select_pattern` 接口不变。新功能通过独立验收后才可默认启用。

## 来源及采用边界

| 来源 | 适用局面与借鉴 | 本项目的处理 |
| --- | --- | --- |
| [GuanZero：行为调节](https://arxiv.org/html/2402.13582v1) | 分别编码让牌、用出牌张数限制对手，以及帮助搭档接手 | 将这些行为拆为诊断与候选理由，不以让牌次数作为棋力指标 |
| [ABL-GD：反绎学习](https://www.lamda.nju.edu.cn/zhangsq/papers/Guandan_ABL%20_CCFAI2025.pdf) | 结合可见对局、手牌估计与专家知识约简动作 | 使用已有合法暗牌世界与规则枚举，不引入其训练网络、数据集或依赖 |
| [开源 Base8 规则策略](https://github.com/Choysang/rlcard-guandan/blob/main/guandan_rlcard/baselines/rule_based/base8/base8_agent.py) | 队友占桌顶时接小单/对子、复杂牌型回应、按剩余牌与炸弹数量夺权 | 固定点数与张数阈值转为正反案例；最终由本项目级牌、过牌规则和团队收益判断 |
| [DanZero+](https://github.com/submit-paper/Danzero_plus)、[DanLM](https://github.com/dashidhy/DanLM)、[FableDan](https://github.com/lrx0716/FableDan) | 候选压缩、公开历史表示和自博弈评测的研究路线 | 只记录方法参考，本轮不引入权重或训练框架，也不使用其排行榜成绩证明本项目实力 |

以上来源于 2026-09-30 核查。论文和社区策略不是本项目规则定义：当前规则包含三次未过 A 退回 2，新规则的过牌锁在新的压牌后重置。升牌、进贡、还贡、接风和冲 A 均由现有引擎结算。

## 实现

`partner_adaptation`、`response_chain` 是独立的研究开关，初始均关闭；前者改变模拟执行策略，后者只保留回应链推荐的根候选，不取代原有快速参考动作或搜索置信度保护。

搭档模型读取每名玩家最近 16 次公开行动，以 8 次行动为半衰期衰减证据，保留均衡/保守/减牌风格的 `[6, 3, 3]` 强先验。领出多张比跟出多张提供更强的减牌证据；礼让队友、紧急封堵及一手出完不计为风格证据。它估计行为偏好，不识别真人身份、真实能力或暗牌。每次根决策只计算一次概率；同一暗牌世界的所有根候选使用同一组风格，分支模拟行为不反过来更新真实搭档模型。

适配续局保留行动者自身手牌与公开信息边界，普通单/对/三回应继续使用轻量枚举；领出、复杂回应和短手牌使用完整合法牌型。风格影响保留结构、消耗炸弹、减牌及是否过牌；合法一手出完和公开的紧急封堵优先于风格。

回应链适用于领出、过牌与接管。根动作后最多执行八次实际行动，涵盖本家回应后的对手反压；只有牌墩实际结束并取得下一墩领出权才记录控场成功。未结束牌墩明确记录为 unresolved，不把“本家有合法回应”当作已收回牌权。

职业最多四个、戴长胜最多八个共同世界，至少完整完成三个才用于候选保留。所有候选共用暗牌与执行风格；预算中断丢弃整轮，包括已计算过的候选。链阶段最多使用根搜索现有剩余时钟预算的 10%，不额外增加等待。没有足够世界时保留原有根候选。若推荐动作尚不在根集合，用它替换一个普通候选，保护原快速参考、最低合法回应、过牌和一手出完候选，不扩大根候选数量。

新诊断记录风格概率、完成世界数、候选替换、实际领出权归属、未决牌墩和预算回退；它们是采样策略结果，不称为不完全信息博弈精确解。

战术案例用于验证行为边界，棋力结论由独立收益门槛给出。以下案例已通过：

| 研究方向 | 本项目规则与成对验证 |
| --- | --- |
| GuanZero 的礼让与帮助搭档 | 搭档安全的对子领出应让牌；对手报单/报双且先于搭档行动时必须封堵。礼让和紧急动作不增加风格证据 |
| ABL-GD 的知识筛选与搜索 | 替换真实暗牌、发牌私有种子后根判断不变；每个共同世界的候选共享执行风格；第四轮超时保留前三个完整世界 |
| Base8 的接管与控炸 | 炸弹/同花顺合法出完优先，逢人配回应合法；本家能压牌后仍受反压不记为收回；头游确定后的接风记录实际下一领出者 |

测试源码见 `tests/test_partner_adaptation.py` 和 `tests/test_ai_partner_validation.py`。修正版全量 843 项通过，覆盖率 84.78%，Ruff、mypy 与覆盖率分项门槛通过，详见 `benchmarks/ai-v7-quality.json`。

## 预先固定的评测

对照为完整 v0.8.6b1 / `77190bf` 快照，使用独立进程，隐藏其他真实手牌和原发牌种子。快照源校验和为 `6c581e13437627856830ba78118d5d8f73d51c4af03cd6ae743b28056ce4bde6`，文件为 `benchmarks/ai-v6-ruleset3-snapshot.zip`。评分继续使用当前冻结的跨局继续值模型；完整比赛则直接记录实际胜负。

| 阶段 | 职业种子 | 戴长胜种子 | 每档规模与工作量 |
| --- | --- | --- | --- |
| 整队开发 | 200000..200031 | 200032..200063 | 每方案 32 对，128 次主搜索评估 |
| 混合搭档开发 | 200100..200131 | 200132..200163 | 每方案 32 对，128 次主搜索评估 |
| 整队独立验收 | 202000..202239 | 202240..202479 | 240 对，256/768 次评估 |
| 混合搭档独立验收 | 203000..203239 | 203240..203479 | 240 对，256/768 次评估 |
| 完整比赛 | 204000..204023 | 204024..204047 | 每档 24 对，256/768 次评估 |

开发比较 `adaptive`、`chain`、`partner_combined`，按整队与混合平均收益差的较小值选择每档一个候选，再锁定源码指纹。开发区间只作诊断；即使开发分数不佳，也完成预定独立验收并如实报告，不重新挑选候选。

所有小局完成完整名次结算；级别、双方比分、A 失败次数与先手在一对中保持一致，只交换策略座位。混合搭档均衡覆盖新手、进阶、高手；同时列出级别与搭档分层，不能把同一副牌的位置当作独立比赛。

默认启用条件：该档整队和混合搭档收益差的 95% 配对区间下界均大于零，每种搭档平均收益差均非负，串行生产时钟与完整比赛合法性检查均通过。样本规模一次固定，验收后不追加种子寻求通过。完整比赛胜率、代理继续值及真人公开回放分支分别报告；混合代理不能证明实际人机胜率。

## 复现

```bash
unzip benchmarks/ai-v6-ruleset3-snapshot.zip -d /tmp/guandan-v7-v6
python -m scripts.ai_partner_validation --baseline-root /tmp/guandan-v7-v6 --stage dev --workers 6
python -m scripts.ai_partner_validation --baseline-root /tmp/guandan-v7-v6 --stage validation --workers 6
python -m scripts.ai_partner_validation --baseline-root /tmp/guandan-v7-v6 --stage full --workers 6
python -m scripts.ai_replay_trial --baseline-root /tmp/guandan-v7-v6 --variant chain \
  --difficulty 3 --fixed-iterations 256 --worlds 32 --ruleset 3 --out benchmarks/ai-v7-replay-3.json
python -m scripts.ai_replay_trial --baseline-root /tmp/guandan-v7-v6 --variant adaptive \
  --difficulty 4 --fixed-iterations 768 --worlds 32 --ruleset 3 --out benchmarks/ai-v7-replay-4.json
python -m scripts.ai_partner_validation --baseline-root /tmp/guandan-v7-v6 --stage clock
python -m scripts.ai_partner_validation --baseline-root /tmp/guandan-v7-v6 --stage report
```

检查点必须匹配源码与完整配方；源或参数改变后使用新的输出目录，不混用已有验收报告。时钟阶段须在固定工作量实验停止后串行运行。

候选源码与配置另外保存在 `benchmarks/ai-v7-experimental-snapshot.zip`；评测源码指纹为 `7903b5b5f70badc1e6d9579fd1cada24fc57343d34964b7eacffbbd030068b43`。该快照的测试与文档在最终结果之前归档，最终验收以工作区的完整结果文件为准。固定动作复核见 `ai-v7-regression-review.json`：30 次动作和原因与 v6 相同，仅配置校验值因两个默认关闭的开关改变。

## 结果

### 开发选择

12 组开发试验共 384 对，全部使用预定种子和 128 次固定主搜索工作量。下表列出平均代理收益差；选择分数为整队与混合搭档两列的较小值。

| 档位 | 方案 | 整队 | 混合搭档 | 选择分数 | 冻结候选 |
| --- | --- | ---: | ---: | ---: | --- |
| 职业 | `adaptive` | −0.008293 | −0.054985 | −0.054985 | |
| 职业 | `chain` | −0.038180 | −0.037019 | −0.038180 | 是 |
| 职业 | `partner_combined` | −0.008281 | −0.078159 | −0.078159 | |
| 戴长胜 | `adaptive` | −0.047738 | −0.007592 | −0.047738 | 是 |
| 戴长胜 | `chain` | −0.057237 | −0.078700 | −0.078700 | |
| 戴长胜 | `partner_combined` | −0.060040 | −0.016004 | −0.060040 | |

独立验收前发现候选准备阶段的截止时间检查不足，以及串行时钟门禁需要分别按档位结算。修正后重新完成全部开发组并冻结；修正前数据保存在 `benchmarks/ai-v7-development-before-clock-fix/`，不用于最终选择或验收。源码冻结之后没有根据独立验收结果调整策略或追加样本。

### 独立验收

四组共 960 对、1,920 个完整小局，均按预定配方完成。收益是冻结的经验跨局继续值下的团队收益差，范围为 −1 至 +1；区间以换座种子对为 bootstrap 单位。

| 档位与方案 | 验收 | 对数 | 平均收益差 | 95% 配对区间 | 候选队头游率 |
| --- | --- | ---: | ---: | --- | ---: |
| 职业 `chain` | 整队 | 240 | −0.006294 | [−0.031255, +0.018927] | 49.79% |
| 职业 `chain` | 混合搭档 | 240 | +0.011836 | [−0.007038, +0.031279] | 52.08% |
| 戴长胜 `adaptive` | 整队 | 240 | −0.148054 | [−0.184207, −0.115187] | 35.00% |
| 戴长胜 `adaptive` | 混合搭档 | 240 | −0.058843 | [−0.087118, −0.030230] | 44.38% |

混合搭档各档位均为 80 对；新手、进阶、高手的平均收益差，职业依次为 **+0.017780 / +0.020908 / −0.003181**，戴长胜依次为 **−0.078775 / −0.072750 / −0.025003**。

两档均未通过默认启用门槛：职业的两个区间均跨零，且高手搭档平均收益差为负；戴长胜的两个区间均完全为负，三个搭档分项也均为负。`partner_adaptation`、`response_chain` 在两个生产档位继续默认关闭，原 v6 基础策略保持启用。战术测试通过说明行为约束落实，不能代替收益验证；开发与验收的种子和工作量均不同，不能把结果差异单独归因于工作量。

原始报告分别为 `ai-v7-holdout-3-chain.json`、`ai-v7-mixed-3-chain.json`、`ai-v7-holdout-4-adaptive.json`、`ai-v7-mixed-4-adaptive.json`。

### 完整比赛、回放与生产时钟

两档各 24 对完整比赛全部完成，合计 96 场、1,077 个小局、83,286 次行动、843 个贡还牌回合，逐局严格重放一致。

| 档位与方案 | 实际整场胜负 | 样本胜率 | 小局 / 行动 / 贡还回合 | 原始记录 |
| --- | --- | ---: | --- | --- |
| 职业 `chain` | 28 胜 20 负 | 58.33% | 581 / 43,071 / 453 | `ai-v7-full-3-chain.json` |
| 戴长胜 `adaptive` | 1 胜 47 负 | 2.08% | 496 / 40,215 / 390 | `ai-v7-full-4-adaptive.json` |

完整比赛只报告实际胜负与流程合法性；各场后续发牌使用起始种子加局号，因此部分牌序重叠，不将这组流程检查的区间解释为独立棋力验收。真人回放保留实际公开前缀，原回放规则为第 2 版，本轮合法分支按第 3 版续局；分支使用合法暗牌与三档代理，不能解释为真实人机胜率。

戴长胜候选在整场样本中明显退化。此结果与独立代理验收的负方向一致，不能因为个别战术案例通过而默认启用；本轮没有据此修改冻结方案或重跑验收寻找通过结果。

回放使用六个实际公开前缀，每个前缀共享 32 个合法暗牌世界，分别由新手、进阶、高手搭档代理续局；三档代理与模型内的均衡/保守/减牌风格是不同概念。每档共 1,152 条合法分支（6 × 32 × 3 × 新旧两方案），全部完成。

职业六个根动作均与冻结对照相同，所有配对差为零；六次链诊断均完整完成四个世界。戴长胜有两处根动作变化，其余四处配对差均为零：

| 公开事件前缀 | 戴长胜根动作变化 | 新手代理收益差 | 进阶代理收益差 | 高手代理收益差 |
| --- | --- | ---: | ---: | ---: |
| 10 | 过牌 → 四张 4 炸弹 | +0.017178 | +0.008337 | −0.000994 |
| 58 | 三张 8 带一对 K → 一对 K | +0.004029 | −0.003645 | −0.017351 |

不利分支完整保存在 `ai-v7-replay-3.json`、`ai-v7-replay-4.json`；适配档记录了公开行动形成的风格概率，链档记录实际领出权归属。戴长胜前缀 87 直接使用已有残局路径，因此没有进入根风格计算。

固定工作量试验和回放停止后，串行完成每档 6 个常规局面、12 个清空五类策略缓存的局面，以及三次连续真实 AI 行动，共 42 次合法决策。全部满足 `1.15 × 预算 + 100ms` 的既有软容差；职业最长 1.020 秒，戴长胜最长 2.009 秒。职业 18 个单独局面中，15 次链评估完成四个共同世界，三次预算中断完成零个世界并回退；戴长胜冻结的是独立适配方案，未启用链。原始逐决策记录见 `ai-v7-clock.json`，不以并行固定工作量试验的耗时证明生产延迟。

最终清单为 [ai-v7-validation.json](../benchmarks/ai-v7-validation.json)，两档 `eligible_for_default` 均为 false。[最终复核](../benchmarks/ai-v7-final-review.json)汇总默认开关、整场流程、时钟、回放和原始文件校验值。默认配置仍关闭两个新开关；完整原始数据、固定动作复核和质量记录均保留。
